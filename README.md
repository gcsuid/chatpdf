# ChatPDF — Chat with Multiple PDFs Using AI

A [Streamlit](https://streamlit.io/) web application that lets you upload one or more PDF documents and ask natural-language questions about them. Answers are generated by Google's **Gemini 1.5 Flash** model via [LangChain](https://www.langchain.com/), with semantic search powered by **FAISS** vector embeddings.

## Why This Project Exists

Reading through long PDF documents to find a specific piece of information is tedious. This project solves that by turning any PDF—research papers, contracts, manuals, reports—into an interactive knowledge base you can query in plain English. Instead of `Ctrl+F` searching for keywords, you ask a question and get a contextual, AI-generated answer drawn directly from the document text.

---

## Features

- **Multi-PDF support** — upload and query several documents at once
- **Semantic search** — questions are matched against document content using vector similarity, not just keyword lookup
- **Contextual answers** — the LLM is given only the most relevant passages and instructed to say when an answer is not in the document
- **Conversation history** — every Q&A pair is tracked within the session along with a timestamp and the source PDF names
- **CSV export** — download the full conversation history as a spreadsheet
- **Clear / Reset controls** — clear just the chat history, or wipe everything including the stored vector index
- **Guided UI** — the question input is disabled until an API key is provided, PDFs are uploaded, and documents are processed, so the app always prompts the user for the next required step

## How It Works

```
┌──────────────┐     ┌─────────────┐     ┌──────────────────────┐
│  PDF Upload  │────▶│  PyPDF2     │────▶│  Text Extraction     │
└──────────────┘     └─────────────┘     └──────────┬───────────┘
                                                     │
                                         ┌───────────▼───────────┐
                                         │  RecursiveCharacter   │
                                         │  TextSplitter         │
                                         │  (chunk_size=10,000,  │
                                         │   overlap=1,000)      │
                                         └───────────┬───────────┘
                                                     │
                                         ┌───────────▼───────────┐
                                         │  Google Embedding     │
                                         │  models/embedding-001 │
                                         └───────────┬───────────┘
                                                     │
                                         ┌───────────▼───────────┐
                                         │  FAISS Vector Index   │
                                         │  (saved to disk)      │
                                         └───────────┬───────────┘
                                                     │
┌──────────────┐     similarity search               │
│  User asks   │────────────────────────────────────▶│
│  a question  │◀────────────────────────────────────┘
└──────────────┘     top-k relevant chunks
        │
        ▼
┌──────────────────────────────┐
│  Gemini 1.5 Flash (LangChain │
│  "stuff" QA chain, temp=0.3) │
└──────────────┬───────────────┘
               │
               ▼
        Answer displayed
        + saved to history
```

1. **Text extraction** — `PyPDF2` reads every page of every uploaded PDF and concatenates the raw text.
2. **Chunking** — `RecursiveCharacterTextSplitter` breaks the text into overlapping 10,000-character chunks so that context is not lost at chunk boundaries.
3. **Embedding & indexing** — each chunk is converted into a dense vector using Google's `embedding-001` model, then stored in a local FAISS index.
4. **Retrieval** — when a question is asked, it is embedded with the same model and the most similar chunks are retrieved from the index.
5. **Generation** — the retrieved chunks and the question are passed to Gemini 1.5 Flash through a LangChain QA chain. The prompt instructs the model to answer only from the provided context and to explicitly say when the answer is not available.
6. **History** — the question, answer, model name, timestamp, and source PDF filenames are appended to the session's conversation history.

## Project Structure

```
chatpdf/
├── app.py            # Entire application — functions + Streamlit entry point
├── requirements.txt  # Pinned Python dependencies (UTF-16 encoded)
├── faiss_index/      # Created at runtime; stores the FAISS vector index
└── README.md         # This file
```

`app.py` is organised into these functions:

| Function | Purpose |
|---|---|
| `get_pdf_text(pdf_docs)` | Extract raw text from uploaded PDF files using PyPDF2 |
| `get_text_chunks(text, model_name)` | Split extracted text into overlapping chunks |
| `get_vector_store(text_chunks, model_name, api_key)` | Create Google embeddings and save the FAISS index to disk |
| `get_conversational_chain(model_name, vectorstore, api_key)` | Build the LangChain QA chain with the Gemini model and prompt |
| `user_input(user_question, ...)` | Orchestrate the full retrieval-augmented generation pipeline |
| `display_conversation(question, answer)` | Render the latest Q&A turn in styled chat bubbles |
| `display_conversation_history(history)` | Render all previous turns in reverse chronological order |
| `create_download_link(history)` | Generate a base64-encoded CSV download link in the sidebar |
| `main()` | Streamlit page config, session state, sidebar, and main chat UI |

## Installation

```bash
# 1. Clone the repository
git clone https://github.com/gcsuid/chatpdf.git
cd chatpdf

# 2. Create and activate a virtual environment (recommended)
python -m venv venv
source venv/bin/activate      # macOS / Linux
# venv\Scripts\activate       # Windows

# 3. Install dependencies
pip install -r requirements.txt
```

> **Note:** `requirements.txt` is UTF-16 encoded. If `pip` raises a parse error, convert it first:
> ```bash
> iconv -f UTF-16 -t UTF-8 requirements.txt -o requirements_utf8.txt
> pip install -r requirements_utf8.txt
> ```

## Configuration

The application requires a **Google AI API key** to call the Gemini model and the embedding API.

You can provide the key in two ways:

1. **Streamlit sidebar (recommended)** — paste the key into the *"Enter your Google API Key"* password field at runtime. The key lives only in the current session and is never written to disk.

2. **`.env` file** — create a `.env` file in the project root:
   ```
   GOOGLE_API_KEY=your_api_key_here
   ```
   `python-dotenv` will load this automatically. Make sure to add `.env` to `.gitignore` so the key is never committed.

Get an API key at <https://ai.google.dev/>.

## Usage Guide

1. **Enter your Google API Key** in the sidebar. A warning is shown until a key is provided.
2. **Upload one or more PDF files** using the *"Upload your PDF Files"* uploader in the sidebar.
3. **Click "Process Documents"** — the app extracts text, splits it into chunks, embeds every chunk, and saves the FAISS index. A success message confirms completion.
4. **Type your question** in the main text input and press Enter. The question input is disabled until steps 1–3 are complete.
5. **Read the answer** displayed in a chat-bubble layout. The bot answers only from the document content; if the information is not present it says so explicitly.
6. **Continue asking** follow-up questions. Every turn is added to the conversation history displayed below.
7. **Download the conversation** at any time using the *"Download Conversation History"* button in the sidebar. The CSV includes columns: `Question`, `Answer`, `Model`, `Timestamp`, and `PDF Name`.
8. Use **"Clear Chat"** to wipe the conversation history while keeping the document index, or **"Reset All"** to start completely fresh (removes history and deletes the `faiss_index/` directory).

## Deployment

### Streamlit Community Cloud (easiest)

1. Push the repository to GitHub.
2. Go to <https://share.streamlit.io/>, connect your GitHub account, and select the repo.
3. In *Advanced settings → Secrets*, add:
   ```toml
   GOOGLE_API_KEY = "your_api_key_here"
   ```
4. Click **Deploy**.

### Docker

```dockerfile
FROM python:3.10-slim

WORKDIR /app
COPY . .

RUN pip install --no-cache-dir -r requirements.txt

EXPOSE 8501

CMD ["streamlit", "run", "app.py", \
     "--server.port=8501", \
     "--server.address=0.0.0.0"]
```

```bash
docker build -t chatpdf .
docker run -p 8501:8501 -e GOOGLE_API_KEY=your_key chatpdf
```

### Linux server with Nginx

```bash
pip install -r requirements.txt
nohup streamlit run app.py --server.port 8501 &
```

Configure Nginx to proxy `localhost:8501` and optionally add TLS via Let's Encrypt.

## Known Limitations

- **Google AI only** — the model selector currently supports only Google Gemini. The codebase is structured to add other providers (OpenAI, Anthropic, etc.) without major refactoring.
- **Session-scoped storage** — the FAISS index and conversation history exist only for the duration of the browser session. There is no persistent database.
- **Single-tenant** — each user manages their own API key; there is no multi-user authentication system.
- **Text PDFs only** — PyPDF2 extracts embedded text. Scanned PDFs or image-based PDFs require OCR pre-processing (e.g. with `pytesseract`) before they can be queried.
- **Local FAISS index** — the vector index is written to `faiss_index/` on the server's filesystem. This does not scale horizontally; a managed vector database (e.g. Pinecone, Weaviate, pgvector) would be needed for a production multi-user deployment.
